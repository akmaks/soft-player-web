# Журнал решений

Формат: дата, решение, почему, что отвергли. Новые записи добавляем сверху.

## 2026-11-20 · Старт: PWA без сборки, файлы внутри приложения, GitHub Pages
- **Стек:** чистые HTML + JS + CSS, без сборщика и фреймворка. Главное правило пользователя — простота;
  плеер помещается в один `app.js` на ~350 строк. Тесты — Playwright на WebKit (только dev-зависимость).
- **Где лежит музыка.** Пользователь хотел «задать папку на телефоне». В iOS Safari это невозможно: нет File System Access API,
  а выбранные через `<input>` файлы — временные копии, доступа к папке после перезапуска нет. Поэтому у плеера своя
  папка (IndexedDB) с подпапками, а «удобная кнопка закинуть аудио» — «+» с выбором файлов или папки целиком из «Файлов».
  Цена: музыка хранится дважды (в «Файлах» и в плеере), исходник после импорта можно удалить.
- **Хранилище — IndexedDB, не OPFS.** Blob в IndexedDB работает во всех iOS 15+; запись в OPFS (`createWritable`) появилась в Safari поздно.
  Байты копируются при импорте (`arrayBuffer`), чтобы не зависеть от временного файла пикера.
  Вызывается `navigator.storage.persist()`. Приложение на экране Домой не попадает под 7-дневную очистку Safari — ставить надо туда.
- **Хостинг:** один публичный репозиторий `akmaks/soft-player-web`, Pages из `main` / корень. Сборки нет — публикуется как есть.
- **Функции v1:** папки/подпапки, создать папку, переименовать, удалить; тап по треку — очередь из треков этой папки;
  «Играть всё, с подпапками»; ⏮ (если прошло >3 с — в начало) ⏯ ⏭, перемотка, перемешивание, повтор выкл/список/трек;
  Media Session (экран блокировки, наушники); при запуске — последний трек на той же секунде, на паузе.
**Отвергли:** Vite/Preact как в garage-drums-web (лишнее для одного экрана); Web Share Target «Поделиться → Плеер»
(iOS не поддерживает для PWA); перемещение файлов между папками, плейлисты, эквалайзер, обложки из тегов (излишества — по запросу).
