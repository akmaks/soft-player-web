# soft-player-web

Простой аудиоплеер для iPhone — веб-приложение (PWA), ставится из Safari через «Поделиться → На экран Домой».
Хостится на GitHub Pages прямо из репозитория. Личный проект пользователя.

Общайся по-русски. Код, идентификаторы, коммиты — по-английски. Коммитим и пушим сразу в `main`.

## Главное правило — простота
- Без сборки и без фреймворков: `index.html` (разметка + CSS), `app.js` (вся логика), `sw.js`, `manifest.webmanifest`, иконки.
  Открыл файл — видишь всё. npm только для тестов (Playwright), в приложение ничего не попадает.
- Функции плеера — стандартные, без излишеств: папки и подпапки, очередь, ⏮ ⏯ ⏭, перемотка, перемешивание,
  повтор (выкл / список / трек), экран блокировки (Media Session), продолжение с того же места.
  Новую фичу сначала примерить к правилу «а без неё можно?». Решения — в `docs/DECISIONS.md`.

## Как устроено
- **Папка — внутри приложения.** iOS Safari не даёт веб-приложению постоянный доступ к папке в «Файлах»
  (нет `showDirectoryPicker`), поэтому файлы копируются в IndexedDB (база `player`): стор `files` — путь → `{ type, data: ArrayBuffer }` (Blob WebKit в приватном режиме сохранять не умеет),
  стор `dirs` — пустые папки. Путь вида `Rock/Live/01 Song.mp3`; папки выводятся из путей.
- Кнопка «+» → «Аудиофайлы…» (множественный выбор из «Файлов») или «Папку целиком» (`webkitdirectory`,
  подпапки сохраняются). Файлы ложатся в текущую папку.
- Играет один `<audio>` из `URL.createObjectURL(blob)`. Состояние плеера (очередь, порядок, позиция, время) — в `localStorage.player`.
- `sw.js` — офлайн: сеть первой, кэш запасным. При изменении списка файлов оболочки поправить `SHELL` и поднять `CACHE`.

## Команды
```sh
npm run dev      # http://localhost:8080, с телефона в той же Wi-Fi: http://<ip-мака>:8080
npm test         # Playwright: WebKit, iPhone 13 mini (375) и 320 pt (Display Zoom)
npm run deploy   # пуш в GitHub, Pages обновляется за 1–2 минуты
```

## Правила
- Всё помещается и нажимается от 320 pt ширины. Новая кнопка — с шагом в `tests/player.spec.js`.
- Баг сначала воспроизводится тестом, потом чинится.
- Репозиторий публичный: никаких личных данных (e-mail — только no-reply GitHub).
- Рутинный прогон тестов — агенту `test-runner` (Haiku) по скиллу `run-tests`. Публикация — скилл `deploy`.

## Проверка перед «готово»
`npm test` зелёный. Звук в фоне и на заблокированном экране, установка на экран Домой, импорт из «Файлов»
и выбор папки целиком проверяются только на живом iPhone — так и говорить пользователю.
